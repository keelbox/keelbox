# 0069: Refuse the agent's SSH to the addresses the box is reached at from outside

Date: 2026-11-13. Status: accepted. Amends [ADR 0011](0011-agent-cannot-reach-admin.md).

## Context
ADR 0011's third layer says the agent cannot SSH into the box at all. Its rule rejects the agent's TCP port 22 to `fib daddr type local`: any address the box itself holds.

Not every address that reaches the box's sshd is one the box holds. On AWS (Lightsail and EC2) and on Google Cloud the public IPv4 address is translated one to one outside the VM, and the VM's interface carries only a private address. A connection from the agent, or from its rootless container, to the box's own public address is therefore not local: it leaves the box, is translated, and comes back to sshd. There the agent gets as far as sshd's key check, where the rule says its connection is refused. The other layers hold (keys only, no forwarded agent), but the local-address rule alone does not enforce the documented rule on those clouds. Hetzner and DigitalOcean put the public address on the interface, so the rule holds there. A home server behind a router that forwards a port has the same shape, often with a port other than 22 on the router.

The box cannot find such an address by itself: it is on no interface, and `$SSH_CONNECTION` shows the private address the connection arrived at. Matching the returning connection on the way in does not work either: an inbound packet has no socket owner, and its source has been rewritten.

## Decision
- **The laptop tells the box where it reaches it.** Every keelbox command over SSH passes `KEELBOX_SSH_ADDRS` to keelbox on the box, beside `KEELBOX_SSH_CONNECTION` ([ADR 0021](0021-close-public-ssh.md)): the address its ssh connects to, and the box's address outside the tailnet when the run goes over the tailnet (`target.ssh.host`, and for a cloud box the public address its provider reports), each with its port. A detached apply keeps the value ([ADR 0063](0063-detached-apply.md)). At most 8 addresses a run.
- **Names are resolved on the laptop.** An address is passed as it is. A name first goes through `ssh -G`, because `target.ssh.host` may be an alias from `~/.ssh/config` that only the laptop can read, and is then resolved by the laptop, every address it has. Resolving on the box was rejected: from inside AWS a public host name resolves to the private address, which is local, so the box would record nothing; and the laptop's resolver is the one whose answer led to the connection.
- **The box keeps what is not its own.** apply asks the kernel whether each address is local (`ip route get`, the lookup `fib daddr type local` makes) and keeps the others in `/etc/keelbox/outside-addresses` (0644 root), one `ADDRESS:PORT` a line. Loopback, link-local, multicast and unspecified addresses are never kept. The port is kept because a forward need not use 22.
- **The record accumulates, up to 16.** A run adds and never removes, so an apply on the box itself, or from a laptop that knows less, keeps what an earlier one learnt. Past 16 the address recorded longest ago is dropped; plan names it. The newest is the one a laptop reaches the box at now, so the oldest is the likeliest to be stale, and an address still in use is recorded again by the next apply that names it.
- **A stale address leaves by hand.** The owner deletes its line and runs `keelbox apply`. keelbox cannot tell an address the box no longer has from a second way in, so it does not guess, and it does not expire by age: a public address named once at creation, by a box used over the tailnet ever after, must stay. For the same reason a line can be added by hand, which is how an address keelbox was never told gets covered. The file is keelbox's and is rewritten whole, keeping every line that is an address; the cap bounds what staleness costs to 16 rules.
- **One reject rule for each.** `AgentNetRules` adds `ip daddr ADDRESS tcp dport PORT ... reject with tcp reset` (or `ip6`) per record after the local address rule, which stays. The rules are written from the parsed addresses, never from the text passed or read. The table is still replaced as a whole and checked with `nft --check` before it is loaded.
- **Doctor** fails when the loaded table lacks the reject rule for a recorded address, and its ok line names what is refused. A doctor run from a laptop that reaches the box at an address not on record reports drift on the `agent-net-addresses` step.
- **What the laptop says is only ever added as a refusal.** The laptop is trusted with the whole box already. A wrong value cannot let the agent reach anything; at worst the agent cannot open one port on up to 16 addresses that are not the box.

## Rejected
- **The cloud's metadata service** (AWS IMDSv2 `public-ipv4`, Google's `external-ip`), asked by root at apply. It would cover a box that only ever ran `keelbox up` on itself on such a cloud, and the time between an address change and the next apply from a laptop. It was left out because it needs one implementation per cloud and still knows nothing of a router, a forward or a cloud keelbox has no code for; because it would have root request and parse an answer from a link-local address on every plan, apply and doctor, which on a machine that is not on that cloud is whatever answers there; and because the laptop already covers the boxes keelbox creates: it passes the provider's public address on every run, tailnet or not, and keelbox reserves a fixed address on AWS and Google Cloud. The record's format does not depend on the source.
- **Asking an outside service for the box's address.** keelbox makes no such calls, and the address a box sends from need not be one it is reached at.
- **Refusing the agent's port 22 everywhere, or to an allowlist.** Git over SSH to any host is ordinary agent work.
- **A config key listing the addresses.** The record takes a line added by hand; a key would be a second place to keep the same list.

## Consequences
- On AWS and Google Cloud the first apply records the public address, and the agent's connection there is reset by the box's firewall like one to a local address.
- Not covered: an address no laptop's keelbox knows. `keelbox up` on the machine itself tells the box nothing, so a router's WAN address in front of a home server, or the public address of a cloud VM set up that way, is not refused unless the owner adds it to the file. `docs/security-model.md` says so.
- An address the box no longer has stays refused for the agent, port 22 or the forwarded port only, until its line is deleted or 16 newer ones replace it.
- Every box gets the file, with only its header where the box holds its own public address.
- The end-to-end checks of ADR 0011 (the agent's `ssh` to the box's address, a container's connection to its port 22) are unchanged: the reject is a TCP reset, as for a local address.
